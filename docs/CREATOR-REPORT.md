# PeerIche 0.8.0 — загрузка видео и подготовка эфиров

## Результат

После авторизации доступен раздел «Вы → Ваши видео»: собственные публикации, их доступность и состояние обработки, постраничное обновление. Публичное готовое видео можно открыть в существующем плеере; закрытое — на сайте сервера. Приложение не добавляет OAuth-токены в ссылки внешнего браузера.

Форма загрузки позволяет выбрать видео через Android Documents UI, собственный канал, название, описание, доступность, отметку чувствительного контента и необязательную обложку. По умолчанию публикация личная. Передача выполняется foreground dataSync service с уведомлением и ограниченным WakeLock. Состояние одного задания сохраняется AtomicFile в noBackupFilesDir без OAuth-токенов. При потере процесса/сети автоматической новой публикации нет: пользователь продолжает существующее задание, сначала сверив принятый объём с сервером. Есть пауза, отмена серверной сессии и отдельное удаление локального задания. Применение обложки после передачи видео можно повторить без загрузки второго видео.

Форма эфира создаёт публикацию для внешней программы (например, OBS), с выбором канала, доступности, сохранения записи и повторного использования. Флаги доступны с учётом конфигурации сервера. Адрес RTMP/RTMPS, ключ и ссылка просмотра получаются авторизованным запросом. Ключ по умолчанию скрыт, показывается в FLAG_SECURE-окне, не сохраняется в задании; копирование выполняется только по нажатию, на Android 13+ буфер помечается как чувствительный.

## Транспорт и защита

Использован существующий AccountSessionManager и единый механизм обновления токена. Каждая операция передачи проверяет выбранный аккаунт. Upload Location допускается только на том же HTTPS origin, с фиксированным путём videos/upload-resumable и единственным upload_id. Редиректы и автоматические сетевые повторы отключены. HTTP 308 принимается только как ответ протокола продолжения, без Location. Проверяются Content-Range, границы блоков, UUID результата, размер ответа, собственный канал, расширение и квоты. Формат и размер обложки ограничены настройками сервера и локальным пределом. В памяти хранится один блок (обычно 1 MiB, максимум 32 MiB).

## Изменённые файлы

- CreatorProtocol.kt — типизированные операции передачи, проверка адресов/диапазонов и сетевой протокол.
- CreatorRepository.kt — возможности сервера, квоты, собственные видео, создание и параметры эфира.
- VideoUploadService.kt — фоновый сервис, пауза/продолжение/отмена, чтение URI и сохранение задания.
- CreatorPage.kt — список, формы загрузки/эфира, прогресс и защищённое окно параметров OBS.
- AccountOperations.kt, AccountSessionManager.kt, PeerTubeAuth.kt — маршруты публикации и интеграция авторизованной передачи.
- YouPage.kt, MainActivity.kt — навигация в «Ваши видео» только после входа.
- AndroidManifest.xml, app/build.gradle.kts — сервис, разрешения и версия. Зависимости и applicationId не менялись.
- CreatorProtocolTest.kt — тесты протокола, квот, адресов, отказов, токенов и смены аккаунта.
- CreatorSmoke.kt, CreatorUiFixture.kt, AuthSmokeInstrumentation.kt — изолированные Android-проверки и UI-данные без внешних публикаций.
- README.md, CREATOR-AUDIT.md, CREATOR-REPORT.md, RELEASE-v0.8.0.md — документация.

Итоговые assembleDebug, assembleDebugAndroidTest, assembleRelease, testDebugUnitTest и lintRelease успешны. 114 модульных тестов, 0 ошибок и пропусков. Lint: 0 ошибок, 82 предупреждения. APK 0.8.0 (versionCode 22) подписан прежним сертификатом SHA-256 57681c30fa42261d1471f54569ce1fc1c432466a551d107f74feba832a70c9bc.

SHA-256 PeerIche-0.8.0.apk: `a3b89d625ff51afde3aeb0f74ba59382e2fc4f91c37cf02b273b272349cc3773`.

Android API 37: прошли проверки реального чтения content URI и AtomicFile, восстановления после потери подтверждения блока, повторной обложки без дублирования видео, паузы, отмены и смены аккаунта. Получение списка видео и параметров OBS проверено через вымышленные ответы API. Основное хранилище аккаунтов не изменяется, тестовые файлы удаляются.

UI проверен на телефоне 393×852 в тёмной теме и планшете 1280×800 в светлой: раздел «Вы», собственные видео, формы загрузки и эфира, выбор файла, ограничения ввода и прокрутка. Падений AndroidRuntime не обнаружено. Ручное нажатие подтверждения эфира в UI-фикстуре было отклонено автоматической проверкой безопасности, поэтому оно не выполнялось; успешное создание по протоколу проверено изолированным Android-тестом.

Реальные загрузки, создание и вещание на сервер пользователя не выполнялись. Совместимость с его плагинами, лимитами, модерацией, длительной фоновой передачей на физическом устройстве и приёмом потока OBS требует проверки в приложении.

Ограничения: одно задание; исходный файл должен иметь известный ненулевой размер и оставаться доступным/неизменным. Android ограничивает dataSync foreground services; после прерывания требуется ручное продолжение. Сервер может удалить неактивную сессию загрузки. При неопределённом результате сначала обновляется список собственных видео, чтобы не создать дубликат. Редактирование/удаление публикаций, загрузка приватных файлов в существующий плеер и работа с камерой/микрофоном не добавлялись. Передача эфира с телефона — следующий этап.
