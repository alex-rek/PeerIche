# Аудит публикации PeerIche

Область: только PeerIche, смартфоны и планшеты. Исходная версия 0.7.1.

Существующие AccountSessionManager и PeerTubeAuthTransport уже обеспечивают HTTPS, привязку операций к аккаунту, обновление токенов и отсутствие автоматических повторов после сетевых ошибок. Их необходимо расширить типизированными операциями публикации; токены не передавать интерфейсу или произвольному upload URL.

Раздел «Вы» реализован YouPage/YouSection в MainActivity. В него добавляется отдельная страница собственных видео. Публичный плеер не меняется; закрытые ролики не передаются ему без механизма доступа.

PeerTube 8.3 OpenAPI: GET users/me/videos, users/me/video-quota-used, config; POST/PUT/DELETE videos/upload-resumable; POST videos/live и GET videos/live/{id}. Возобновляемая загрузка использует Location при инициализации, Content-Range для блоков и PUT bytes */total для проверки принятого объёма. HTTP 308 здесь является подтверждением неполной загрузки, а не редиректом. URL продолжения должен оставаться на том же HTTPS origin и фиксированном API-маршруте.

Решение: foreground dataSync service, один сохраняемый черновик передачи, persistable URI-доступ Android, ограниченные блоки в памяти, ручные продолжение/отмена, проверка квоты/форматов/канала. При потере процесса или сети не создавать новый ролик автоматически. Состояние сохранять в app-private noBackupFilesDir через AtomicFile, без OAuth-токенов. Секрет эфира получать по запросу и показывать в защищённом окне, не сохранять в черновик.

Этап включает загрузку файлов и создание/получение параметров эфира для OBS. Камера, микрофон и отправка RTMP с телефона — следующий этап. Новые зависимости не требуются.

Источники: https://docs.joinpeertube.org/api-rest-reference.html и https://github.com/kukhariev/node-uploadx/blob/master/proto.md .
