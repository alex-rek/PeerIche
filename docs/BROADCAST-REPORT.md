# PeerIche 0.9.0 — трансляция с телефона

## Что изменено

Создана страница «+» с тремя прокручиваемыми режимами: загрузка, трансляция, параметры канала. По умолчанию открывается трансляция. Кнопка появляется только при активном аккаунте без needsLogin; иначе прежние «Подписки». Верхние вкладки подписок не удалены, прежняя страница «Ваши видео» и очередь загрузки сохранены.

Камера и микрофон требуют runtime-разрешения Android. Предпросмотр локальный: до нажатия начала нет RTMP-передачи, открытия микрофона или создания публикации. Нужен свой канал и сервер, разрешающий live. Можно создать эфир с названием, описанием, доступностью и записью либо использовать ожидающий эфир аккаунта. Серверные настройки существующего эфира сохраняются. В приложении есть накладные кнопки фронтальной/задней камеры, отключения микрофона, заставки, ориентации и фонарика при поддержке, редактирование параметров, ссылка для просмотра/шеринга и подтверждение завершения.

BroadcastCoordinator связывает существующий CreatorRepository/AccountSessionManager с RootEncoder. Ключ получается только от сервера аккаунта, не сохраняется в Preferences/Intent/уведомление, не выводится приложением в ошибки. Передаётся только в RTMP-подключение к адресу, предоставленному сервером. RTMPS предпочитается существующим CreatorRepository; проверяются системная цепочка сертификата и SAN-имя узла, без доверия всем сертификатам и без автоматического понижения до RTMP при TLS-ошибке.

BroadcastService объявлен camera|microphone, запускается из видимой Activity после разрешений, показывает уведомление с завершением и возвратом к трансляции. Перезапуск после убийства процесса не запрашивается. Ошибки подключения, кодировщика, смена/выход из аккаунта останавливают передачу и освобождают источники. При уходе с предпросмотра камера освобождается; активный эфир может продолжаться через foreground service. Bitmap-заставка заменяет источник камеры, SilenceSource заменяет AudioRecord. Заставка масштабируется с сохранением пропорций. При смене ориентации до эфира меняется формат кадра; в эфире сохраняется разрешение кодировщика.

Настройки эфира и картинка хранятся отдельно для аккаунтов без секретов. В параметрах можно изменить название и описание только собственного канала: перед записью проверяется список каналов текущего аккаунта, маршрут использует локальное имя канала из этого списка. Идентификатор канала, настройки качества и картинка могут сохраняться как локальные предпочтения.

## Проверки

Итоговые assembleDebug, assembleDebugAndroidTest, assembleRelease, testDebugUnitTest и lintRelease успешны. 125 модульных тестов, 0 ошибок/пропусков; lint — 0 ошибок, 89 предупреждений. Проверены прежние функции, меню авторизации, допустимые параметры, формирование адреса без утечки ключа, валидация канала и TLS-имени, исключение завершённого и чужого эфира из повторного выбора.

Визуально проверены телефон 393×852, горизонтальный размер 852×393 и планшет 1280×800; гостевая кнопка подписок, кнопка «+» после входа, нижний выбор трёх режимов, параметры, состояния микрофона/камеры, пропорции заставки и пересоздание preview Surface при изменении размера. Проверены тёмная и светлая темы. AndroidRuntime без падений.

На task-эмуляторе emulator-5556 Android API 37 выполнены существующие проверки входа/Keystore, серверных действий и возобновляемой загрузки, а также запись сгенерированного изображения/PCM-тишины в MP4. MediaExtractor подтвердил H.264 640×480, AAC и реальные пакеты обеих дорожек. Смена источников проверяется внутри записи. Микрофон при этом не открывается, тестовый MP4 удаляется.

Для проверки RTMP использован tools/rtmp_fixture.py и adb reverse tcp:19350 tcp:19350. Синтетический тест получил на приёмнике 66 видеопакетов, 129 аудиопакетов и по одной конфигурации AVC/AAC. Проверка настоящего BroadcastService с виртуальными камерами AVD получила 43 видеопакета, 185 аудиопакетов и конфигурации. Проверены запуск foreground service, переключение back/front, замена камеры заставкой, освобождение камеры через CameraManager.AvailabilityCallback, поворот, остановка при смене аккаунта. Звук оставался выключенным. PeerTube API в этом тесте — только GET к объектам в памяти, используется существующий вымышленный UUID, никаких новых публикаций на PeerTube не создаётся.

## Ограничения

Приём конкретным PeerTube-сервером и RTMPS-интеграция с его сертификатом/прокси требуют проверки на устройстве пользователя. API сервера определяет live, модерацию, длительность и запись. Обрыв завершает клиентскую передачу; пользователь выбирает существующий ожидающий эфир или новый. После закрытия процесса нет автоматического возобновления захвата. Выбор ожидающих эфиров использует первую страницу собственных видео; более старые можно открыть через «Ваши видео»/сайт сервера. Эффекты, ретушь, локальная запись эфира и дополнительные объективы помимо фронтальной/задней камеры не реализованы. При отсутствии подходящего кодировщика/камеры можно выбрать более низкое качество. На физическом устройстве длительный эфир и поведение при звонках отдельно не проверялись.
