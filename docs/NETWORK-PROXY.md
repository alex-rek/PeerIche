# Настройки сети и прокси

В «Настройки → Сеть» добавлены параметры по образцу локального RussTube: без прокси, HTTP, SOCKS5, адрес, порт, необязательные логин и пароль, сохранение, проверка соединения и сброс. Файлы RussTube не изменялись.

По умолчанию прокси выключен. Адрес вводится как имя узла или IP, без схемы и пути; порт — отдельным полем, 1–65535. IPv6 допускается в квадратных скобках. Проверка соединения выполняет публичный HTTPS-запрос к example.com без данных аккаунта.

## Подключённые соединения

- PeerTube API, вход и операции аккаунта, поиск, каталог серверов и подборки.
- Обложки и аватары Coil.
- Media3: видео, HLS-плейлисты, сегменты, перемотка и субтитры.
- Скачивание и загрузка видео, HTTP-загрузка субтитров и проверка обновлений.

Настройки применяются при создании новых запросов, в том числе в уже созданных Retrofit/Coil-клиентах. После сохранения ленты обновляются. Текущее длительное соединение может завершиться с прежним маршрутом; для немедленного применения к нему нужно заново открыть ролик или перезапустить передачу.

RTMP-передача эфира с телефона, управляемая SDK загрузка моделей перевода и внешние браузеры не используют этот HTTP/HTTPS-слой. Ограничение указано в форме настроек.

## Хранение и авторизация

Конфигурация хранится в отдельном файле `noBackupFilesDir/network-proxy.bin`, зашифрованном AES-GCM с отдельным ключом Android Keystore. Пароль не записывается в обычные SharedPreferences, saved instance state, логи или диагностические сообщения. Данные аккаунтов и база приложения не менялись.

HTTP-прокси получает свои реквизиты через Proxy-Authorization, включая CONNECT. Authorization аккаунта остаётся отдельным заголовком. SOCKS5 использует ограниченный адресом и портом прокси процессный Java Authenticator. Проверка сертификатов TLS не отключается.

Недоступность прокси и неверные реквизиты не приводят к прямому подключению. Если сохранённую конфигурацию невозможно расшифровать, новые сетевые запросы приостанавливаются до повторного ввода или явного сброса. Старые пулы соединений закрываются вне UI-потока.

## Основные изменения

- `ProxyRouting.kt` — валидация и маршрутизация, динамический Call.Factory, HTTP/SOCKS5-авторизация.
- `ProxyNetwork.kt` — Keystore/AtomicFile, состояние настроек и уведомление об изменениях.
- `PeerIcheApplication.kt`, `AndroidManifest.xml` — инициализация до запуска Activity/Service и общий сетевой клиент Coil.
- `NetworkSettingsPage.kt`, `SettingsScreen.kt` — раздел «Сеть» и форма настроек.
- `PeerTubeApi.kt`, `ConfiguredSearch.kt`, `PeerTubeAuth.kt`, `CreatorProtocol.kt`, `ServerCatalog.kt`, `AppUpdates.kt`, `LocalTranslation.kt`, `SubtitleCueAdapter.kt`, `VideoDownloadService.kt` — подключение сетевых запросов к прокси.
- `PlaybackService.kt`, `app/build.gradle.kts` — HTTP-источник Media3 OkHttp, с сохранением обработки локальных файлов и авторизованного доступа к видео.
- `MainActivity.kt` — обновление выдачи после изменения маршрута.
- `values*/network_proxy.xml` — подписи на всех 11 языках интерфейса.
- `ProxyRoutingTest.kt`, `ProxySmoke.kt`, `AuthSmokeInstrumentation.kt`, `tools/proxy_fixture.py` — проверки с локальными тестовыми прокси и синтетическими реквизитами.

## Проверки

- `assembleDebug`, `assembleDebugAndroidTest`, `testDebugUnitTest`, `lintDebug` — успешно; 182 модульных теста без ошибок.
- JVM: HTTP, HTTPS CONNECT и SOCKS5, авторизация, удалённое разрешение имени назначения, сохранение Authorization аккаунта, смена параметров без пересоздания фабрики запросов и отсутствие прямого обхода при ошибках.
- Android: HTTP/SOCKS5 с авторизацией и без неё; один кешированный API-клиент, изображения Coil и чтение диапазона видео через все четыре режима; реальное воспроизведение с отключённым звуком через авторизованный CONNECT.
- Android: зашифрованное хранение и повторное чтение конфигурации; неверный пароль блокирует соединение; создание запроса после смены прокси на UI-потоке не выполняет сетевое закрытие TLS-сокетов в этом потоке.
- Интерфейс: ввод и сохранение, проверка HTTP/SOCKS5 с авторизацией, восстановление после пересоздания Activity, русские/английские подписи, телефон/планшет и сброс.
- Предоставленный пользователем внешний прокси: авторизация и HTTPS GET публичного API PeerTube успешны через HTTP 8080 и SOCKS5 1080. Пароль вводился скрыто и не записывался в исходники или APK.
